# Explicit runtime host (offline)

`RuntimeHost.start` is the optional loaded-release entry point when `activateRuntimeHost`, `activateAutomation` and `activateStorage` are all explicitly true. It starts the App paused, creates one native snapshot reader, subscribes separately to actual Sync and changed-State events, and starts the quarter-second timer. The host owns both subscriptions, the timer and the App. UI unload or a failed subscription/timer unwinds those resources. The default `Loader.start` path still starts the inert UI only.

The host builds `NativeEventAdapter` from the injected current Remotes folder and State module. It requires a directly parented `Sync` RemoteEvent with `OnClientEvent` and the saved `State.onChanged` callback; both subscriptions must return disconnect handles. `NativeSnapshotReader` labels only the Sync callback as complete; a duplicate changed notification with identical data does not downgrade it. Before creating an App, before every full Sync and immediately before a queued native invocation, `CompatibilityGate` compares a read-only observation of the actual account, place ID, game version and reviewed source fingerprint. A mismatch closes the host before that Sync or call is planned. The observer must read current client state rather than echo the configured identity.

`RuntimeHost` constructs its transport from `NativeCallPlan` and `NativeDispatchAdapter`, storage from `ExecutorStorageAdapter`, and the timer from `ExecutorRuntimeAdapter`. The raw injected runtime API supplies asynchronous `after` and `defer` plus `cancel`; the host ignores any caller-provided `invoke`. It constructs `NativeRemoteResolver` from the current Remotes folder and resolves the exact `RemoteFunction` name at dispatch time, checking class and current parent while preserving trailing `nil` arguments. Host shutdown closes the resolver, including queued callbacks. The storage API must supply file/directory, JSON and real SHA-256 functions; absent or malformed capabilities block startup. The host also expects account-bound identity, a monotonic clock, strict durable checkpoint storage and the release-pinned modules. No current-client observer, Remotes folder, State module, executor primitives or production manifest is supplied yet; this module does not make the preview live.

The next integration must discover and validate the current client's actual State event and full Sync event, then supply the native call adapter and cached source proofs. Run a read-only compatibility check before enabling any mutation, and verify each result from a newer Sync rather than a remote return alone.

The broker also rechecks its two-second snapshot age and revision when a queued callback starts. If the callback is late or a newer Sync/State observation arrived, it does not invoke a remote. The write-ahead attempt remains unconfirmed and follows the 45-second skipped/unconfirmed rule, because a scheduled callback is not proof of a server-side cancellation.

The host clears externally supplied `shopQuoteSource` and `rewardsSource` values. If the current Shop modules are supplied, it constructs the pinned `NativeQuoteSource` with the reviewed release/fingerprint. In current-client mode it obtains the DailyBuff rule, Group ID and Group lookup from `NativeClientBindings`, ignoring caller-supplied stand-ins, then constructs `NativeRewardsSource`. A full Sync schedules an asynchronous membership refresh when the cache is absent or older than 20 seconds, with at most one queued/running refresh and a shutdown fence. The result can be used only on a subsequent full Sync. Missing or invalid sources leave those features blocked, while host shutdown closes any constructed source. The live client exposes the expected module/method shapes; execution of the edited binding in that client remains unverified.

Before creating the deferred release commit, `python tools/build_release_manifest.py --preflight` checks the current working tree for missing required modules, duplicate module IDs and the loader's module-count limit without writing a manifest. The normal `--commit <full SHA>` mode still requires exact committed bytes.
