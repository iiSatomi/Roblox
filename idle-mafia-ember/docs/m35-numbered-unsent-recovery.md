# Numbered checkpoint attempts and definite-unsent recovery

Checkpoint now assigns a safe-integer local request ID on every saved attempt and persists a monotonic highwater alongside pending records/usage. Resolve, reply persistence and allowance changes preserve it. Caller IDs are discarded. Legacy unnumbered records remain loadable for feature-specific state recovery but cannot gain definite-unsent proof from a new numbered fact. Invalid/duplicate/out-of-range IDs or mismatched pending envelopes refuse load. Exhaustion refuses before storage. This ID is local recovery metadata, not a native Heist/recall sequence allocator.

Broker's definite no-invocation paths may append a separate exact scope/request/proposal/before/baseline fact. They never let a stopped callback rewrite the main checkpoint. SHA-256 of the storage scope keeps side keys bounded; missing hash/write proof leaves the action held. A fresh runtime may clear only an exact non-lifecycle single action with that fact. Custodial Crew replacement retains its own owner/review path. Returned and unknown invoked actions cannot become unsent; there is no replay or success count. Late recovery preserves skipped history and cooldown.
