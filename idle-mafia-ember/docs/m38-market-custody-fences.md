# Market custody owner fences and prepared review

MarketTransactions now serializes same-loaded-module writes by scope, re-reads and compares the complete expected stored envelope before each change, and advances a persisted generation only after a successful write. An obsolete loaded owner cannot overwrite a newer preparation or a committed-but-falsely-reported write. Reload while a writer yields refuses; closing the tab closes its custody owner. An already-started save may finish after close, but subsequent sending transitions refuse and a fresh owner retains the saved custody.

Legacy version-1 envelopes without generation retain their exact transaction; the next successful metadata change starts generation 1. No usage is reset and no saved transaction is emitted. This is a metadata compatibility step, not execution/release migration.

PreparedReview/DiscardPrepared are local primitives that compare the complete exact prepared transaction, scope and generation. Tampered, reused, closed, sent or observed records cannot be discarded. A future connected UI must add paused/no-pending checks and one-use expiring preview confirmation; this milestone does not advertise that UI or activate listing/buy/withdraw. Legacy rental state observation now uses the same observed-clock extension bounds as the new rental path, replacing the loose ±120-second test.

Independent Luna read-only review found no actionable custody lost-update/post-close-write flaw; no tests or edits by the agent. Parent regressions cover stale loaded owners, yielding write/reload/unload, ambiguous persisted failure, exact prepared-only discard, generation compatibility and mismatched rental expiry. The shared checkpoint change in m39 is verified with this milestone: **1292 run, 1291 passed, one external official-analyzer skip**, 33.677 seconds; 277 modules/catalog matched. No live client/MCP/Stamina/spending/Git write/publication. Fresh-module/process atomic ownership remains open.
