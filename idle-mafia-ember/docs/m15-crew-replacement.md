Native Auto Roll start remains blocked: `CrewAction("autoroll", slot, tier, targetRarity)` carries no reserve, spend limit, attempt count or controller request identity. `CrewReplacement` instead handles one selected ordinary dismissal and one funded ordinary hire. The selected target must be home, uninjured, untrained and unequipped; protected/ambiguous members are refused. An existing empty slot blocks dismissal. Config hire odds must support the chosen rarity. Separate permanent-dismissal permission defaults false; per-hire Cash ceiling, total replacement spend and cycle cap default zero. Minimum home count and reserve remain explicit. Legacy Legendary/Mythic policy values map to source rarities 5/6; Custom uses its selected rarity. Existing profile keys remain valid and all limits stay visible for every goal.

Current six-header usage/controller proof and exclusive slot-owner proof are required. `CrewReplacementTransactions` persists the target/quote/baseline before dismissal, then follows prepared dismissal → sent dismissal → observed empty → prepared hire → sent hire → observed member. Only a successful write-ahead transition arms one direct `SubmitCall`. Reload restores custody without restoring that arm. The positive dismissal reply plus a newer full Sync must show only the selected target empty. Hire requires that target be the sole empty slot because the native hire call has no destination argument. Exact acquisition and Cash debit are required before final cleanup. Intermediate empty custody cannot be discarded as completed.

Unknown/sent stages never replay automatically. A failed immediate preflight consumes its live emission arm; the saved sent record then needs explicit reconciliation/review, not a blind retry. `AcceptReply` matches the sent action key before changing live state; a late dismissal reply cannot disarm a newly prepared hire. Close fences callbacks and sends. Original dismissal evidence survives the hire stage/reload, and failed persistence preserves the previous record. Dismissal has no server-side member-identity argument: fresh full-roster signatures and optional real `healId` protect observed client custody, without claiming atomic server identity validation or rollback.

Crew owns optional helper/transaction factories, owner attachment, policy projection and continuation planning. Disable, changed settings, mismatched owner or recovered prepared state stops new work while retaining saved custody. `NativeCallPlan.withCrew` optionally delegates only replacement calls to the domain helper.
