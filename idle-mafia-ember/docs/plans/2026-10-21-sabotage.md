# Separate Heist sabotage: offline slice — implemented locally

The saved `HeistsTab` calls `HeistAction("sabotage", row.id,
localSequence)`. A new `sabotage` descriptor uses only a current
unqueried board, original row ID, known local player ID and current
native costs/limits. It excludes self, friend and Family rows,
requires eligible level, unexpired run, no personal help and an
available per-run sabotage slot. The separate switch remains OFF by
default. Use the legacy temporary cap of five sent attempts per
native day and reserves of five Favors and ten energy.

Store each sent attempt atomically with the unresolved action before
dispatch, including unconfirmed sends. Preflight rechecks the exact
row and costs. Confirmation needs a positive reply and newer board
showing one more personal sabotage and the exact Favor debit for the
same owner; do not count a send or local ledger increment as success.
The mutation sequence belongs to a future verified native adapter.

Tests: self/friend/Family exclusions, resource and daily limits,
numeric/string row IDs, exact-row evidence, fake checkpoint restart
and shared broker. No real call, purchase or paid-controller bypass.

Implemented through `SabotageState`, `Sabotage`,
`SabotageEvidence`, registry/runtime injection and the existing
checkpoint. See `../m6-sabotage.md` for limits.
