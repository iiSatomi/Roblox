# Task 22 utility tabs

October 27, local implementation and fake-UI verification only. Overview, Profiles, Settings and Activity remain separate tab modules. They introduce no services, native gameplay calls, timers or subscriptions. Production JSON transfer uses the existing injected storage codec; UI-only callers without one get an explicit unavailable message instead of inert transfer buttons.

- Overview displays the active feature/phase, up to three selected-feature blockers, unconfirmed count and up to five affected features, and registered runtime adapter count. Registration is not advertised as functional/live acceptance. Storage faults, active action and duplicate exposure remain separate facts. Action keys and request tokens are not shown.
- Profiles separates current saved choices and their modified state from the selected saved name, staged choices and next-launch autoload. Saved-name callbacks compare the current selection before updating the name field, so obsolete asynchronous callbacks cannot change the autoload target. Save/preview/refresh/autoload remain account/place scoped. Rename uses one profile-record write, rejects an existing destination, preserves the original on failed persistence, and requires autoload for the old name to be disabled first because that flag is a separate record. It does not change any gameplay preference.
- Export serializes only `{schema, values}` into a text field. Import decodes bounded JSON (1–65536 bytes), validates existing keys/types/exclusive choices and runtime availability, then stages a scalar copy. Named/imported profiles are replacements: missing preferences use catalog defaults, while ordinary single-control updates retain patch semantics. The staged difference view includes those defaults. Import never executes code, saves a profile or activates choices. Invalid input leaves the prior preview and current choices intact. Apply stays separate and pauses the session. All-off first launch and explicitly enabled, unpaused custom autoload retain their existing tests.
- Settings ignores superseded asynchronous theme callbacks. A refused or throwing theme update restores the last applied choice, preserves the actual theme label and displays failure. Reset fences queued selections; closed UI callbacks do nothing. F8 visibility, window centering, reduced motion and session-only theme persistence retain existing behavior. Only previously used Ember APIs were involved; the primary Ember reference was read.
- Activity keeps 20 bounded local command labels and the latest 10 sanitized public gameplay labels, displaying the latest five. Outcome descriptions distinguish sent/replied from replicated confirmation and explain stale preflight, checkpoint failure, ignored late reply and unconfirmed deadline. Tokens, action keys, arbitrary raw reasons/replies and account payloads never enter the gameplay history.

Verification: new tests in `test_profile_management.py`, `test_utility_runtime_views.py` and `test_settings_tab.py` cover transfer without activation, corrupt/unknown/oversized data, storage/rename failures, selection vs current-profile state, bounded metadata and theme races/refusals/unload. Review reproduced stale saved-name callbacks and sparse-profile inheritance; both gained failing regression cases before the fixes. Follow-up profile review independently passed **13 tests**. The final full integrated suite ran **1013 tests, 1012 passed, one skipped** in 42.638 seconds. The skipped check needs the external official Luau analyzer (`LUAU_ANALYZE`); it is not a skipped gameplay case. Catalog check and manifest preflight passed at **256 modules**. Scoped whitespace check passed. No commit or publication occurred.

Tab-local C/T is complete for the behavior above; current-client UI acceptance remains open. A pending/imported profile never bypasses that owner.
